Referências de hooks

Os cinco momentos em que um script pode entrar.

Um hook é um script seu que o Claude Code executa num momento definido. Ele recebe um JSON no stdin com o contexto (cwd, hook_event_name, tool_name, tool_input). Para bloquear, o script escreve a mensagem no stderr e sai com código 2; sair com 0 deixa passar.

EventoQuando dispara
SessionStartInício ou retomada de sessão — bom para injetar contexto do dia ou conferir pré-requisitos do projeto.
UserPromptSubmitAntes do Claude processar a sua mensagem — dá para acrescentar contexto ou barrar um pedido inteiro.
PreToolUseAntes de executar qualquer ferramenta (Bash, Edit, Read) — é onde vivem os três hooks de CRO da seção 4.
PostToolUseApós executar uma ferramenta com sucesso — bom para validar o que acabou de ser escrito, rodar lint, registrar log.
StopQuando o Claude termina de responder — bom para notificação, checklist final ou resumo da sessão.
Catálogo de hooks prontos

github.com/lucianfialho/awesome-claude-code-hooks

Exemplos organizados por evento, para copiar e adaptar. A documentação oficial completa está em code.claude.com/docs/en/hooks.

A regra para saber se algo deve virar hook: se você precisa que aconteça sempre, e não dá para aceitar que o modelo esqueça uma vez, é hook. Se é orientação que admite julgamento, é CLAUDE.md ou skill.

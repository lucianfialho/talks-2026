Ato 2 — Claude Code CLI Palestra 02
Como eu inicializo na prática
sessão de análise — modo completo
claude \
  --plugin-dir ~/Code/claude-dev-pipeline \
  --dangerously-skip-permissions \
  --remote-control \
  --append-system-prompt "no suggarcoat"
plugin-dir → skills e hooks do pipeline
skip-permissions → sem confirmações
remote-control → monitoro do celular
append-system-prompt → instrução fixa de tom
pipeline automatizado — não-interativo
cat events.csv | claude -p \
  --append-system-prompt "analise os dados de CRO, responda em PT-BR" \
  --max-turns 5 \
  --output-format json
-p → print mode, sai após resposta
max-turns → evita loop infinito
output-format json → parse fácil no pipeline

Ato 2 — Slash Commands Palestra 02
/comando
um atalho que dispara uma sequência inteira
Sem slash command
"Me ajude a verificar se o teste A/B tem SRM, calcule o chi-quadrado, verifique a distribuição de tráfego entre as variantes usando a tabela events_clean no DuckDB, e me diga se posso declarar vencedor..."
Você reescreve toda vez. Sem garantia de consistência.
Com slash command
/srm-check
Uma palavra. Sempre a mesma lógica. Sempre o mesmo output estruturado.
Slash commands são a interface entre você e o Claude. Quanto mais específicos pro seu negócio, mais valor você extrai.

Ato 2 — Hooks Palestra 02
Hooks
guardrails que rodam antes do Claude agir
Momentos disponíveis
SessionStart
Início ou retomada de sessão
UserPromptSubmit
Antes do Claude processar sua mensagem
PreToolUse ← usamos hoje
Antes de executar qualquer ferramenta (Bash, Edit, Read)
PostToolUse
Após executar uma ferramenta com sucesso
Stop
Quando Claude termina de responder
PreCompact
Antes de compactar o contexto da sessão
28 hooks no total — docs.claude.ai/hooks
O hook que vamos usar hoje
settings.json — PreToolUse
{
 "hooks": {
  "PreToolUse": [{
   "matcher": "Bash",
   "hooks": [{
    "command": "bash validate.sh"
   }]
  }]
 }
}
Antes de qualquer Bash rodar, validate.sh verifica se SRM check foi feito. Se não foi, bloqueia. Não é prompt. É código.
